# Deployment extraction: phases 0–1

Implemented 2026-10-16. Offline only; no controllers were moved and no hardware
connection, native rebuild, recovery or baseline modification was performed.

## Phase 0 — extraction inventory

[`source-inventory.json`](source-inventory.json) inventories 288 tracked source
inputs across deployment, portable motion sources, deployment scripts and related
tests, with SHA256, proposed destination/disposition, imports, top-level definitions,
CLI markers, configuration markers and hard-coded host-path line numbers.
It also records 85 referencing consumer files and the source revisions/dirty
status/file hashes of the separate Franky and ROS 2 source repositories.

Assignments marked `split` require function-level separation during extraction;
they are deliberately not assertions that an entire file has one owner. Static
imports/text references do not prove completeness of dynamic or external consumers.
The first M4 slice must preserve the dependency mappings and tests identified here.

Verify the captured source inputs without importing or changing them:

```bash
python scripts/migration/inventory_deployment.py \
  --source /path/to/franka-rl \
  --franky /path/to/modified-franky \
  --ros /path/to/modified-franka_ros2 \
  --output deployment/migration/source-inventory.json --verify
```

Omit `--verify` and use a **new** output filename to capture a later snapshot;
existing outputs are never overwritten by the tool. Source paths are command-line
inputs, not runtime dependency resolution rules. Generated caches/builds/venvs are
excluded by using tracked source files. Historical raw data remain in place.

## Phase 1 — portable contracts and golden fixtures

The separate `robot-learning` checkout now defines `contracts` 0.0.2 with motion,
encoder feedback and session/command/receipt/fault types. See its
`docs/physical_motion_contracts.md`. Existing Cartesian-delta/VLA and LIBERO
schemas remain unchanged. Runtime and the learning checkout pin contracts 0.0.2;
other hosts/repos are not automatically upgraded.

[`../../tests/parity/fixtures/legacy-parity-v1.json`](../../tests/parity/fixtures/legacy-parity-v1.json)
records the following inputs/outputs and exact legacy source hashes:

- Incremental position projection, normalized joint velocity and held J7.
- Previous-reference/raw-action observation ordering (29 values).
- Joint PD and the current shared-previous-command slew/filter processing order.
- Independently reset and untouched torque-processing instances.
- Kinematic/dynamic projectors and curve normal/tangent decomposition.
- URDF FK/Jacobian and encoder-model frame/tool-transform adapter behavior.
- Sticky supervisor fault state/reason after subsequent stop/completion attempts.

Fixtures were generated by the explicitly selected legacy **pure Python** sources.
The encoder adapter uses a fake model and URDF FK uses an archived model: neither
constitutes calibrated FK validation against the currently attached arm. These
are golden inputs for testing future extracted implementations, not evidence that
a new runtime already matches native controllers. Selective-reset fixtures check
independent numerical state; full runtime queue/reference reset parity remains a
Phase 2–4 obligation.

The separate native test receipt in
[`offline-provenance.json`](offline-provenance.json) records 23 passing test cases
and 82 assertions, including native stop and guard cases, from the **existing**
modified-fork binary. It includes binary, fixture and modified wheel/library
hashes. No fresh native rebuild/source-binary equivalence is claimed.

Regenerate fixtures explicitly into a new output file when reviewing source changes:

```bash
python scripts/migration/capture_parity.py \
  --source /path/to/franka-rl --output /external/artifacts/new-parity.json
```

This generator requires NumPy/PyYAML and deliberately loads legacy Python helpers.
It is an extraction tool, not installed runtime behavior. Ordinary fixture tests
need no legacy checkout, Franky, libfranka, ROS or Isaac.
